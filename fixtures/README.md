# Fixtures for trajectory-level equivalence testing

Prepared in response to the authors' request (2026-09-01): exact command lines,
commit hash, seeds, and serialized networks with initial states underlying
representative points, so that implementations can be compared at the level of
individual trajectories rather than ensemble means.

## Provenance

- Explorer commit: see `MANIFEST.json` (`commit` field); generated by `npm run fixtures`.
- Engine: `src/engine/` + `src/lab/run.ts` (`ENGINE_VERSION` in the manifest).
- Every run is fully determined by `(params, seed)` through the public API:
  `mulberry32(seed)` generates the network, then the initial state, exactly as
  `runTrajectory` / `runClassicalCycleTail` / `runPbnPiecewise` consume it.
- mulberry32 has no Python counterpart, so seeds regenerate runs bit-exactly on
  the TS side only. The serialized network and initial state are the portable
  ground truth for the Python side.

## Network format

Identical to the parity harness (`scripts/parity/export.ts` writer,
`reference/parity.py` `build()` reader): node list, per-context
`{regulators, lut}` per node, entangled pairs, Kripke accessibility. LUT values
use the reference implementation's own value shapes (Booleans, `(2, b)`
contradiction tuples encoded as `{"__tuple__": [2, b]}`, `"possible"`,
`("necessary", b, 0.85)`, `"superposed"`, mutable-entry dicts). Validated:
`parity.build()` parses these files and the reference simulator runs them with
the recorded initial states unmodified.

## Points (10 runs each; see MANIFEST.json for full parameters and rationale)

| file | what it pins |
|---|---|
| `classical-k34.json` | Contested classical point (N=100, K=3.4, T=10^6). Both measurement paths on the identical trajectory: full extractor vs cycle-tail shortcut. In these runs the two agree on the cycle found (same V in all ten) and differ on Ω through the dwell-time convention (P = T−μ vs the detector's revisit-based count). Nine runs lie between 9×10^-4 and 4×10^-1; the tenth (seed 901007) settles on a 2-cycle and gives Ω ≈ 2×10^-6 under both paths, with P differing by exactly one, which is the λ−1 gap between the two conventions. |
| `classical-k21.json` | Classical control below the contested region. |
| `pbn-poisson-k21.json` | PBN, σ=0.1, Poisson: global episode detector vs `measure_kd_piecewise` analogue. Observed means: ~1.3×10^-1 vs ~1.7×10^-5 on the same networks and initials (context draws differ by construction). |
| `pbn-exponential-k30.json` | PBN exponential-topology plateau point. |
| `paraconsistent-k21.json` | Same seeds under both semantics: shipped random-bit fallback vs local majority resolution. Observed means: ~1.1×10^-2 vs ~1.6×10^-4. |
| `modal-k21.json` | Modal evaluation-order question, both semantics. |
| `quantum-k21.json` | Paired-state coupling question, both semantics. |
| `arm-k21.json` | ARM under both semantics (Ω = 0 in our runs at μ = 0.4; the published ARM conclusion is robust to the never-called `mutate_rule`). |

Each run row carries: `seed`, `initial` (the exact initial state), `network`
(serialized as above), and `metrics` per measurement path (Ω, V, P, KD,
realized K).

## Ensemble CSVs

`csv/fig1-sweep.csv` and `csv/fig2-sweep.csv`: the Explorer's full Fig. 1/2
reproductions (T = 10^6, ≤300 networks per K, CI half-width δ = 0.02), one row
per (series, K): mechanism, semantics, Ω mean, CI half-width, sd, network
count. Source JSONs: `public/data/fig1.json`, `public/data/fig2.json`.

## Reproducing

```
npm install
npm run fixtures        # regenerate fixtures/*.json + MANIFEST.json
npm run reproduce       # regenerate the ensemble sweeps (long)
npm run parity          # TS-vs-reference parity harness
```
